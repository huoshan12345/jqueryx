# Code Review

Review code from the top down. First determine whether the feature under review has a sound overall design: the problem it solves, whether it belongs in this package, its responsibility boundaries, data and concurrency model, lifetime, extensibility, and relationship to neighboring types. Only when the overall design is sound should the review proceed to detailed API and implementation concerns such as naming, signatures, validation, algorithms, locking, allocations, and code style. If the overall design is unsound, report that as the primary finding and recommend an appropriate redesign or removal rather than spending review time on details that would be discarded after the redesign.

Whenever the user requests a code review, treat API and signature design as a first-class review concern, not optional polish. Review class names, method names, parameter names, local variable names, and public API names to ensure that they accurately describe their purpose, read naturally, are easy to understand, and remain consistent throughout the codebase. Also review complete signatures, including overload structure, parameter order and types, return types, generic constraints, nullability, cancellation support, synchronous versus asynchronous forms, and whether public APIs accurately express their behavior. Report questionable names or signatures even when the implementation itself is correct.

Review the purpose and implementation of every relevant class and method. If an abstraction addresses an identifiable problem but its current responsibility, usage model, or overall design is clearly unsuitable, report the design issue and propose a more appropriate direction. If the intended purpose of a type or member is unclear or appears arbitrary, ask the user what problem it is intended to solve before judging whether its design is sound. Never invent an intention merely to justify the existing code.

When the user is addressing a set of review findings, verify every item they claim to have fixed. During that verification, add sufficient regression tests to cover the corrected behavior.
